# SuperGold ERP – QA Fix Pack (2026-11-03)

## Changes applied

### 1. Atomic bill number allocation
- Added `backend/models/Sequence.js` and an atomic MongoDB sequence increment for bill numbers.
- The counter is seeded from the highest existing bill number (minimum starting value 1000), preserving existing bill numbering.
- Sequence collection is created during backend startup so the first transaction does not need to create a collection inside a MongoDB transaction.
- This prevents two concurrent bill requests from both reading the same latest bill number and choosing the same next number.

### 2. Duplicate bill submission / retry protection
- Added a unique sparse `idempotencyKey` field/index to bills.
- Billing form sends a stable `Idempotency-Key` for the current save attempt.
- Frontend blocks repeated clicks while a save is in progress and displays a Saving state.
- If a request is retried with the same key (including after a network interruption), the backend returns the already-created bill instead of creating another one.
- The key is rotated only after the bill save flow succeeds; failed/uncertain attempts retain the same key.

### 3. Prevent false bill-save failures after commit
- Cashbook sync runs after the bill transaction commits. Previously, a cashbook sync error could return HTTP 500 even though the bill was already saved, encouraging the user to submit again.
- The backend now returns the saved bill successfully and includes `cashbookSyncWarning: true` if cashbook sync fails. The UI warns the operator to check Cashbook.

## Deployment note
- Deploy backend and frontend together.
- On startup, the backend creates the sequence collection and synchronizes Bill indexes. Take a MongoDB backup before deploying.
- Do not delete existing bills or reset the sequence collection. Existing bill numbers are retained and the counter initializes from the current maximum bill number.
